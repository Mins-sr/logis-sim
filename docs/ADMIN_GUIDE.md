# 管理者／ホスト／倉庫運営者の入口

管理者／ホスト／倉庫運営者は、実験世界の中の1つの役割です。実験環境の起動・停止、参加状況の確認、シミュレーション操作、倉庫資源の状況管理を担当します。既存のシステム権限`HOST`に対応し、画面では「管理者として開く」から参加します。以下では「管理者」と略します。

同一端末で試すローカル実験用です。実験責任者と開発・保守担当は、この実験全体を設計・支援する立場です。

startは、初期準備の後、接続中のDocker環境にある**物流システム以外の起動中コンテナをすべて自動停止**します。CVATなど別の作業や、Composeに所属しないコンテナも対象です。ポート競合の有無に関係なく、確認入力なしで停止します。Composeの所属が`tof-logis`のコンテナと、停止済みコンテナは停止対象にしません。

停止対象の名前・所属を表示し、コンテナ・イメージ・ボリューム・データは削除しません。停止確認に失敗した場合はDB起動前に中断します。停止した他サービスは、物流システムの起動失敗時・終了時にも自動再開しないため、必要なときは利用者がそのサービスの手順で再開してください。Docker自体やホストの通常プロセスは停止しません。

1. Docker・Compose、Python 3.12、Node.js 20／npmを準備します。
2. Macは [`scripts/start.command`](../scripts/start.command) をダブルクリック、Linuxは [`scripts/start.sh`](../scripts/start.sh) を実行します。必要な初期準備もこの入口が行います。
3. 起動結果に表示されたURLを開き、「管理者として開く」を選びます。既定ポートは8080です。変更済みパスワードは画面のログイン欄から入力します。
4. シミュレーションの操作、案件・車両・庫内資源を確認します。workerの「起動済み」は業務機能全体の正常性を保証しません。
5. 終了時はプロジェクト内で `scripts/dev.sh compose down` を実行します。DBの名前付きボリュームは残します。`-v`は付けません。

役割を試し直すときは「役割を選び直す」を使います。同じブラウザの別タブは入口へ戻るため、ログイン・切替は1タブずつ完了させてください。

起動失敗時は表示された工程と `.local/logs/start/` を確認します。ポート競合や画面のない環境での利用は[起動・検証手順](TESTS.md)を参照してください。

## 倉庫資源の確認

同じ管理者画面の「庫内リソース」で、配送と庫内作業の状況を確認します。

1. ステージングの使用パレット数と容量を確認します。
2. 各バース（ドック）の使用中・空きを確認します。
3. 案件・車両の状況と突き合わせ、詰まりや想定との差を実験責任者・開発保守担当に共有します。

画面はローカルのシミュレーション用です。実倉庫設備の操作や本番稼働の監視機能は前提にしません。実装範囲の確認は[構成案内](ARCHITECTURE.md)から必要な箇所を参照してください。

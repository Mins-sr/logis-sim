# 開発・保守担当の入口

開発・保守担当は、実験に必要な機能の実装・検証、不具合修正、運用文書を担当します。AIによる支援もこの役割に含めます。

実験責任者とともに実験全体を支える上位の立場です。実験世界の中には荷主、ドライバー／運送事業者、管理者／ホスト／倉庫運営者の3役があります。「上位」は設計・支援の立場を示し、システム上の追加権限を付与しません。

1. [ルートの指示書](../AGENTS.md)と、変更先に適用される指示書を読みます。人間専用の `docs/readme.md` は閲覧・編集・検索・レビューの対象外です。
2. [現在の作業](TASK_STATE.md)で未完了事項を、[構成案内](ARCHITECTURE.md)で対象箇所を確認します。設計書の記述をそのまま実装済みと判断しません。
3. 環境の起動は[管理者／ホスト／倉庫運営者の入口](ADMIN_GUIDE.md)、開発と検証は[検証手順](TESTS.md)を使います。依存関係の準備は明示的なsetup、または初期準備を含むstartから行います。
4. 振る舞いを変更する場合は先に回帰テストを追加し、対象検証と必要な独立レビューを行います。未実施の確認は明記します。

既存の未コミット変更、DB、パスワード、名前付きボリュームを保持します。個人実験に必要な小さい変更を優先し、コミット・pushは明示的に依頼された場合だけ行います。
